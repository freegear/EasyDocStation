# User

## 1. [개선] 사용자 정보 편집에서 중복 이메일 저장 차단

### 1.1 증상

사용자 정보 편집 화면에서 이메일을 이미 다른 사용자가 사용 중인 주소로 변경할 수 있으면, 로그인 식별과 사용자 관리에서 혼동이 발생할 수 있다.

### 1.2 요구 사항

- 같은 메일 주소를 사용하는 사용자가 있으면 이메일을 업데이트하지 않는다.
- 화면에는 다음 메시지를 표시한다.

```text
같은 메일 주소를 사용하는 사용자가 있습니다. 메일 주소를 변경해 주십시요
```

### 1.3 구현

- `PUT /api/auth/me`는 입력 이메일을 소문자/trim으로 정규화한다.
- 현재 사용자 외에 같은 이메일을 가진 사용자가 있으면 `400`과 위 메시지를 반환하고 저장을 중단한다.
- 프런트엔드는 서버 메시지를 사용자 정보 편집 화면 상단 경고 영역에 그대로 표시한다.
- 신규 DB 스키마는 `users.email` unique 제약을 유지한다.
- 기존 운영 DB에서는 중복 이메일이 없을 때만 unique 인덱스를 생성하고, 이미 중복 데이터가 있으면 인덱스 생성만 건너뛴다.
